Trust architecture

Governed by design, not policy

AnchorWithin is built on AOS — the Anchor Operating System. Every external action is governed, logged, and human-approved.

🔐 AOS Approval Engine
No autonomous publishing. No autonomous outreach. Every action that touches external systems routes through the AOS approval pipeline — human tap required, Telegram-delivered.
AOS v1.0
🛡️ FENRIR Quality Gate
All API-delivered content is scored across 5 weighted categories: voice, brand alignment, visual quality, market fit, and compliance. Minimum 7/10 to pass. Hard-fail for voice or brand below 15/25.
FENRIR Standard
💳 Stripe Payment Governance
Keys are issued and revoked through Stripe webhooks — no manual key management. Checkout triggers issue. Subscription cancel triggers immediate revoke. No orphaned keys.
Stripe-verified
📋 Dead-Letter Queue
Failed actions retry up to 3 times with exponential backoff, then route to dead-letter. No silent failures. Emergency stop flag halts all agents instantly across the system.
AOS Event Bus
📊 Budget Enforcement
Per-agent daily spend limits and hourly task rate enforcement. Agents cannot exceed budget without explicit human override. Protects capital from runaway loops.
Budget Governor
🔍 Verity Trace Layer
Every API delivery is stamped with a trace ID. Audit any call: what was served, when, under which quota state, and which agent requested it. Full accountability chain.
